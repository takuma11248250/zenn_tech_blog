データ領域では、BIツールなどのOSSを自前でホストして運用しているケースが多いと思います。ただ最近は、既存のBIツールではなく、Next.jsなどを使って自由にダッシュボードやレポートを作りたいという要望が増えてきた実感があります。

そのときにネックになるのが、デプロイ環境の管理です。誰かがそれぞれ違う環境に立ててしまい、属人化して誰も面倒を見られなくなる、というのはよくある話ではないでしょうか。今回はその解決策として使えそうな、OSSのセルフホスト型デプロイ基盤「[Coolify](https://coolify.io/)」を紹介します。

## 課題: 「自由に可視化したい」が生む属人化

BIツールの範囲で収まっている間は、運用は比較的シンプルです。しかし「BIの表現力では物足りない」「もっと自由にUIを組みたい」という声が上がってくると、Next.jsなどのWebアプリとしてダッシュボードを自作する流れが出てきます。

ここで問題になるのが、**アプリを動かすためのデプロイ環境**です。作った人が個人のVPSに立てる、別の人はクラウドのマネージドサービスにデプロイする、といった形でバラバラの環境が乱立すると、次のような状態に陥りがちです。

- 作った本人しか環境の構成を把握していない
- 担当者が異動・退職すると誰も触れなくなる
- 似たようなアプリなのに、デプロイ方法がプロジェクトごとに違う

**可視化ツール自体は軽い気持ちで作れても、デプロイ環境の管理コストがボトルネックになってしまう**わけです。

## Coolifyとは

[Coolify](https://coolify.io/) は「Self-hosting with superpowers」を掲げる、OSSでセルフホスト可能なデプロイプラットフォームです。VercelやHeroku、Netlify、Railwayの代替として位置づけられています。

![Coolifyのトップページ](/images/01.png)
_Coolifyの公式トップページ_

主な特徴は次のとおりです。

| 項目         | 内容                                                                                            |
| ------------ | ----------------------------------------------------------------------------------------------- |
| 対応サーバー | 自前のVPS、Raspberry Pi、EC2、DigitalOcean、Linode、Hetznerなど。SSH接続さえあればデプロイ可能  |
| 対応スタック | 幅広い言語・フレームワークに対応し、Docker互換のサービスなら280以上をワンクリックでデプロイ可能 |
| SSL証明書    | Let's Encryptによる自動発行・更新                                                               |
| Git連携      | GitHub、GitLab、Bitbucket、Giteaと連携し、Push to Deployが可能                                  |
| バックアップ | S3互換ストレージへのDB自動バックアップ                                                          |
| 料金         | セルフホストであれば永続無料                                                                    |

![Coolifyの機能一覧](/images/02.png)
_Coolifyが提供する機能の一部_

Gitにpushするだけでデプロイできる、SSLも自動で面倒を見てくれる、といった点は、まさにVercelのような体験をセルフホスト環境で得られるイメージです。

## なぜ「共通デプロイ環境」として良いと思うのか

冒頭の課題に戻ると、Coolifyが解決してくれるのは「**デプロイ方法を1つの場所に集約できる**」という点です。各自がバラバラに環境を作るのではなく、Coolify自体を共通基盤として1つ用意しておけば、誰が作ったアプリでも同じ手順でデプロイ・管理ができます。

特に相性が良いと感じるのは、次のようなケースです。

- 機械学習のようにGPUを使う重い処理は不要で、**可視化だけのような軽いアプリ**
- **まずはスモールに動くものを関係者に見てもらいたい**段階
- 正式にサービスへ組み込む前の、**POC(概念実証)レベル**のもの

こうした段階では、「デプロイをどうするか」を考える手間そのものが無駄です。Coolifyに乗せてしまえば、作った人はアプリのロジックに集中でき、**デプロイを意識せずにみんなに見せる**ことができます。

逆に、GPUを使う機械学習用途などの重い推論処理などは、Coolifyの想定するユースケースから外れます。あくまで「Webアプリやデータベースを手軽にセルフホストする」ためのツールだと捉えるのが良さそうです。

## POCで終わらせず、スケールするときの移行先

もう1つ大事だと思っているのは、Coolifyを「終着点」にしないという考え方です。POCとして出したものが事業的なインパクトを持ち始め、本格的にスケールさせたいとなった段階では、**データエンジニアがKubernetesなどのちゃんとした基盤に載せ替えて管理する**というステップに進めばよいと考えています。

つまり、Coolifyの役割は「属人化を防ぎながら、小さく速く価値検証をするための共通POCデプロイ環境」であり、価値が確認できたものは、しかるべきタイミングで本番運用に耐える基盤へ移行する、という住み分けです。**最初から全部をk8sで構えるのではなく、POCの段階ではCoolifyで身軽に、価値が確認できたものだけ本格的な基盤に載せ替える**、というグラデーションを作れるのが、Coolifyの一番のメリットだと感じています。

## 実際にPOCしてみた

言葉で説明するだけでは実感が湧きにくいので、実際に手元のサーバーにCoolifyをセルフホストし、簡単なダッシュボードアプリをデプロイしてみました。

### セルフホスト環境の構築

サーバーにCoolifyをインストールすると、まずRoot Userのアカウント作成画面が表示されます。

![Coolifyのアカウント作成画面](/images/03.png)
_セルフホストしたCoolifyの初期セットアップ画面_

アカウントを作成してログインすると、「New Resource」画面からアプリケーションやデータベースなど、デプロイ対象を選択できます。Public/Private Gitリポジトリはもちろん、DockerfileやDocker Composeからのデプロイにも対応しており、選択肢の多さが伝わってきます。

![New Resource画面](/images/04.png)
_デプロイ可能なリソースの一覧_

### 最初のデプロイは失敗

手始めに、公開されているStreamlitのサンプルリポジトリをデプロイしてみました。しかし、結果は`Exited`でした。

![デプロイログ(進行中)](/images/05.png)
_ビルド自体は進んでいく_

![デプロイログ(失敗)](/images/06.png)
_11回再起動を試みたのちrestart limitに達して停止_

ビルドそのものは成功しているものの、コンテナ起動後にクラッシュを繰り返し、再起動の上限に達して停止していました。**Coolify自体がうまく動かないというより、デプロイ対象アプリ側の設定(ポートやヘルスチェックなど)を合わせ込む必要がある**、という典型的なつまずきどころだと感じました。

### 自作ダッシュボードのデプロイは成功

次に、Next.jsで作った簡易的な売上ダッシュボード(ダミーデータ)をリポジトリからデプロイしてみたところ、今度は問題なく`Running`状態になりました。

![デプロイログ(成功)](/images/07.png)
_bi-dashboard-pocはビルドからロールアウトまで問題なく完了_

実際にブラウザでアクセスすると、狙いどおりダッシュボードが表示されました。

![デプロイしたダッシュボード](/images/08.png)
_デプロイに成功したダッシュボード(PoC/ダミーデータ)_

さらに、Coolifyの管理画面からブラウザ上のターミナルでコンテナに直接接続できることも確認できました。デプロイしたアプリの中身を少し確認したい、というときにSSHクライアントを別途用意しなくて済むのは地味に便利です。

![ブラウザ上のターミナル](/images/09.png)
_コンテナに直接ログインして状態を確認できる_

### POCを通して分かったこと

一度Coolify自体をセットアップしてしまえば、あとは各アプリのリポジトリを指定するだけでデプロイが完了します。**うまくいかない場合も、Deployment LogやTerminalからその場で原因を追える**ため、「デプロイしたはいいが中で何が起きているか分からない」という状態にはなりにくい印象でした。冒頭で触れた、属人化しがちなPOC環境の共通基盤として、十分実用に耐えると感じています。

## まとめ

- BIツールに収まらない「自由に可視化したい」ニーズが増えると、デプロイ環境が属人化しやすい
- [Coolify](https://coolify.io/) はOSSでセルフホスト可能なデプロイ基盤で、Push to Deployや自動SSLなど、Vercelに近い体験を自前サーバーで得られる
- GPUを使う重い処理には向かないが、**可視化のような軽いアプリをPOCレベルでスモールに見せたいときには有用**
- 実際にデプロイしてみても、失敗時のログ確認から成功後のターミナル接続まで一通りブラウザ完結で行えた
- 事業インパクトが大きくスケールが必要になったら、データエンジニアがk8sなどの本格的な基盤へ移行すればよい

デプロイ環境の管理コストに悩んでいるチームであれば、まずは共通の受け皿としてCoolifyを試してみる価値はあると思います。
