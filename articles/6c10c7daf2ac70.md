## de-questとは

[de-quest](https://de-quest.com/) は、データエンジニアに必要なスキルを体系立てて学べる個人開発の学習教材アプリです。技術的なスキルだけでなく、実務で評価される行動特性まで含めて、次の5つのスキルルートに分けて構成しています。

| ルート | 学べる内容 |
| --- | --- |
| 技術力 | Linux/Git/SQL/GCP/dbtなど、実務で使う技術そのもの |
| コミュニケーション能力 | 技術力を最大化するための土台となる、事業部やチームメンバーとの円滑な連携 |
| 主体性・自立性 | 指示待ちにならず、自分で課題を見つけて動く力 |
| 問題解決力 | トラブルや制約に対して、筋道を立てて解決する力 |
| チーム貢献度 | チームの成果を最大化するための立ち回り |

**各ルートは20ステージ+総集編1ステージの、合計21ステージ構成**です。1ステージずつ順番に進めていくことで、断片的な知識ではなく、実務のシチュエーションに沿った形でスキルが積み上がっていくように設計しています。

## 4択の実践問題形式と、ハンズオン形式の使い分け

de-questのステージは、大きく2種類の形式で構成しています。

**コミュニケーション能力、主体性・自立性、問題解決力、チーム貢献度の4ルート**は、実際のデータエンジニア業務でありがちなシチュエーションを題材にした4択の実践問題形式です。各ステージに10問ずつ用意しており、単なる知識確認ではなく、「一見良さそうに見えるが実務では避けるべき選択肢」を誤答に混ぜることで、**実務での判断力そのものを試す設計**にしています。

一方で**技術力ルートだけは、問題集ではなくハンズオン形式**を採用しています。実際に手を動かさないと定着しないためです。

## コミュニケーション能力・主体性/自立性・問題解決力・チーム貢献度ルート

4択形式の4ルートは、いずれも序盤は「まだやったことがない・自信がない」ジュニア向けの内容から始まり、終盤は経験者でも惰性で手を抜きがちな場面を扱うシニア向けの内容へと難易度が上がっていく構成になっています。

**コミュニケーション能力**は、報連相の型から始まり、事実と解釈を分けて伝える、So What/Why Soで論点を整理する、ビジネスと技術の間を翻訳するといった段階を踏み、最終的に信頼関係の構築まで学びます。

**主体性・自立性**は、指示を待たずに次の行動を考えるところから、進捗を自分から報告する、改善提案を自分から出す、新技術を自主的に導入提案すると段階を上げていき、最終的にプロジェクト全体を自律的に推進できるところまでを扱います。

**問題解決力**は、着手前に目的・背景を整理する、エラーログを正しく読む、なぜなぜ分析で根本原因を掘り下げる、解決策のトレードオフを説明するといったステップで力をつけ、最終的に問題を先読みして予防し、解決プロセスを組織全体に展開するところまでを扱います。

**チーム貢献度**は、困っているメンバーをサポートする、ナレッジをドキュメント化する、技術的負債を認識し改善提案する、チーム最適の視点で技術的判断を下すというステップを重ね、最終的にチームのビジョンや文化の醸成にまで踏み込みます。

## 技術力ルート——Output重視のハンズオン形式

技術力ルートは、Linuxの基礎からアーキテクチャ設計まで、データエンジニアに必要な技術要素を一気通貫でハンズオン化しました。

- Linux/CLIの基礎〜応用(ログ監視・自動アーカイブスクリプト)
- Git/GitHubの基礎〜応用(feature branch運用・コンフリクト解消・rebase)
- Pythonの基礎(公開APIから取得したデータをCSV/JSON保存する簡易ETL)
- SQLの基礎(ECサイト風ミニDBでJOIN・集計・サブクエリ)
- ネットワークの基礎(DNS・CIDR計算・HTTP/HTTPS)
- GCPの基礎〜応用(Cloud Run JobsとBigQuery外部テーブルによる1本のELTパイプライン構築)
- Terraformの基礎〜運用(手作業で作ったGCPリソースのコード化)
- データセキュリティの基礎〜実装(カスタムIAMロール・権限棚卸し)
- コンテナの基礎〜応用(Docker/Kubernetes)
- データ監視の仕組み化(Audit Log・Cloud Monitoring・SLI/SLO設定)
- OSSの構築(Airbyteのローカルデプロイと同期実行)
- BigQueryの基礎〜応用(パーティション・クラスタリング・ウィンドウ関数)
- オーケストレーションツールの基礎〜応用(Airflowでのパイプライン構築)
- アーキテクチャ設計(Datastream/Pub/Sub/GCSバッチの比較検討)
- CI/CDの基礎〜応用(GitHub Actionsでのdbt test自動実行とマージブロック)
- dbtの基礎〜応用(staging/marts構成のモデリング)
- データ品質の基礎〜応用(意図的な不正データ混入によるテスト検出)
- モデリングアーキテクチャの基礎〜応用(dbt公式のstaging/marts構成に沿ったスタースキーマ設計)
- 新技術の調査・評価・提案(uvの導入検討、pip+venvとの速度比較)
- コード設計とレビューの実践(欠陥のあるコードへの指摘とリファクタリング)
- 総集編(学習ログ集計基盤という1つのミニプロジェクトに、20ステージの要素を統合)

すべてのステージで、**「作って終わり」ではなく必ず動作確認の手順を含める**ことにこだわりました。コマンドを打って終わりではなく、期待する出力や終了コードまで確認して初めてステージクリアになる、という構成です。

## どんな人におすすめか

de-questは、主に**ジュニア〜中堅層のデータエンジニア**を想定して作っています。各ルートは序盤ほど「まだやったことがない・自信がない」人向けの内容から始まり、経験を積むにつれて、経験者でも惰性で手を抜きがちな場面や、チーム・組織を意識した判断が問われる終盤の内容へと難易度が上がっていきます。

技術力ルートに関しても、コマンドやオプションの意味を一つひとつ丁寧に説明する構成にしており、**未経験に近い段階からでも手を動かしながら追いつける**ことを意識しています。

一方で、チームをまとめる立場の人にとっても、メンバーに何を身につけてほしいかを言語化した「育成の型」として使える構成になっていると思っています。

## まとめ

- データエンジニアに必要なスキルを5ルート(技術力、コミュニケーション能力、主体性・自立性、問題解決力、チーム貢献度)に分けて学べる個人開発アプリ[de-quest](https://de-quest.com/)をリリースしました
- 4ルートは実務シチュエーション型の4択問題(各21ステージ×10問)、**技術力ルートだけは問題集ではなく実際に手を動かすハンズオン形式**にしています
- 技術力ルートは全21ステージで、Linux/Gitの基礎からGCP・dbt・アーキテクチャ設計まで一気通貫でカバーし、**動作確認までを含めたOutput重視の構成**にしています
- 主にジュニア〜中堅層のデータエンジニアを想定していますが、チームをまとめる立場の人にとっても「育成の型」として使える構成にしています
